# GOAL.md - Stemmagraph v403: Portability Dashboard Fase 2 Export Foto ZIP Lokal (VISION item 2.8 lanjutan)

- **Item Aktif:** Stemmagraph v403 export foto anggota sebagai ZIP lokal sebagai fase 2 Portability Dashboard
- **Tujuan:** VISION 2.8 menuntut unduhan seluruh data keluarga (GEDZIP, JSON ber-schema, foto ZIP). GEDZIP tuntas, JSON export tuntas v402 (merge 5362ef8); foto ZIP belum ada. Foto tersimpan LOKAL via PHOTO_UPLOADS_DIR (server/index.ts baris 206-215, fallback data/uploads; photoUrl String? schema baris 145 berupa penanda file/endpoint GET), sehingga ZIP dibaca langsung dari disk tanpa unduhan eksternal.
- **Pilar / AC (kontrak AC1-AC6):**
  1. AC1: modul pure src/lib/portability/photoZipExport.ts: buildPhotoZipManifest via exportPrivacyGate (sumber kebenaran penyaringan privacy, tanpa duplikasi logika), entry name deterministik berbasis id, byte foto disuntik sebagai map (tanpa I/O di modul pure), schemaVersion "stemmagraph-photo-export/1", waktu sebagai parameter.
  2. AC2: route GET /api/v1/trees/:treeId/export/photos di server: 401 tanpa auth, 404 tree bukan milik user, 200 application/zip attachment dengan header aman pola v402 (nosniff, no-store, no-referrer, filename regex whitelist); baca file dari PHOTO_UPLOADS_DIR lokal; file hilang di-skip dan dilaporkan jujur di manifest entry skipped, BUKAN gagal total; TANPA guard SSRF unduhan eksternal karena nihil fetch URL eksternal.
  3. AC3: batas agregat ZIP 200 MB: total ukuran foto terpilih dihitung dari disk sebelum zip, terlampaui = 422 kode AGGREGATE_LIMIT pola 422 v401/v402; per-file tetap ikut validasi ukuran upload eksisting; UI cukup spinner tanpa progress streaming.
  4. AC4: ExportControls aksi keempat Export Foto ZIP di samping PNG/JPG/PDF/GEDCOM/GEDZIP/JSON, mode privacy clean/full mengikuti state existing pola v402 (full owner-only server-side), i18n id dan en parity penuh (key export.photosButton + export.photosError).
  5. AC5: test vitest: unit modul pure (determinisme dua panggilan identik, schemaVersion, penyaringan privacy, batas agregat), test route (401/404/200 dengan magic bytes ZIP PK, skip file hilang jujur, 422 agregat, full non-owner 403), test wiring ExportControls (aksi memicu unduh, error state).
  6. AC6: gates penuh: prisma validate 0, tsc 0, lint 0 error (baseline 9 warning), build 0, vitest scope hijau, em dash 0 di baris tambahan, NIHIL dependency baru (fflate 0.8.3 existing, zipSync pola exportGedzip baris 165-188); pure core terjaga (tidak ada kode komersial).
- **Non-Goals:** tanpa progress streaming, tanpa round-trip import foto, tanpa fetch URL eksternal (SSRF keluar scope karena foto lokal), tanpa ubah format GEDZIP/GEDCOM/JSON eksisting, tanpa re-encode gambar server-side, tanpa main/staging.
- **Inline VISION:** VISION-stemmagraph 2.8 Portability Dashboard fase 2 (foto ZIP), prinsip 8 portabilitas dibuktikan bukan dijanjikan, pilar 1 dan prinsip 3 portability pledge.
- **Dasar evidence:** draft Sena wake-165 (preseden Gramps media archive, webtrees media export) dengan KOREKSI PM first-hand wake-166: foto LOKAL via PHOTO_UPLOADS_DIR sehingga guard SSRF tidak diperlukan; batas agregat 200 MB keputusan PM (zipSync in-memory fflate, jaga memori); manifest tetap via exportPrivacyGate.
- **Verifikasi PM:** feasibility first-hand wake-166 pasca merge v402 (PHOTO_UPLOADS_DIR baris 206/215, photoUrl schema baris 145, fflate 0.8.3 package.json baris 50). GOAL diturunkan PM Ardi (26 Okt 2026, wake-166). Dispatch implementasi = window berikutnya (batas 3 tindakan wake ini tercapai).
