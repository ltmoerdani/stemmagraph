# GOAL.md - Stemmagraph v416: UI Komentar Profil Fase 2 (VISION Pilar 2 ekor v415, kolaborasi keluarga)

- **Item Aktif:** Stemmagraph v416 UI Komentar Profil Fase 2: permukaan komentar profil anggota di MemberDetailSidebar yang mengikat API v415 (POST/GET/DELETE) lewat adapter CommentApi, add-only di branch improve/stg-v416-comment-ui.
- **Tujuan:** VISION-stemmagraph Pilar 2 kolaborasi keluarga: keluarga bisa berdiskusi di profil anggota. Fase 1 (v415, merge 359de80) membangun backend lengkap; fase 2 menghidupkan UI-nya. Tanpa fase 2, endpoint komentar tidak punya pemakai.
- **Spesifikasi (feasibility first-hand PM wake-179):** model Comment v415 hidup TANPA kolom soft-delete (koreksi atas draft Sena, hapus = hard delete lewat route DELETE). Routes hidup: POST /api/v1/members/:memberId/comments, GET keyset pagination cursor, DELETE /api/v1/comments/:commentId (penulis ATAU owner pohon). Adapter: CommentApi { listComments, postComment, deleteComment } + accessor getCommentApi() sudah ter-push; mock dan supabase adapter null sehingga UI sembunyi (pola getConsentApi). Komponen CommentsSection dengan optimistic add + rollback + hide-on-failure (pola MergeApprovalsPanel) sudah ter-push dan terverifikasi PM (AC1+AC2, komit 7a49efe, 53c90df, d9d2696, f55e576, 569e4ee). Remount per member via key, baseline lint tetap 9 warning.
- **Pilar / AC (kontrak AC1-AC6):**
  1. AC1 (SELESAI): adapter add-only: tipe CommentItem/CommentApi + implementasi RestAdapter (listComments after cursor, postComment body, deleteComment) + accessor getCommentApi(); mock dan supabase null; nihil perubahan tipe atau method existing.
  2. AC2 (SELESAI): komponen CommentsSection di-mount MemberDetailSidebar: fetch listComments saat mount, gagal atau API null = section tidak tampil; form tambah dengan optimistic add yang diganti entri riil setelah sukses dan rollback plus error inline bila gagal; i18n namespace commentSection id/en parity penuh; remount bersih per ganti member.
  3. AC3: hapus komentar role-preserving: tombol hapus hanya untuk komentar milik user login (owner pohon boleh hapus semua, backend sudah menegakkan); dialog konfirmasi eksplisit pola APG (fokus awal pada aksi non-destruktif, Escape menutup); delete TANPA optimistic (konfirmasi dulu, panggil API, error inline verbatim bila gagal); daftar diperbarui setelah sukses hapus.
  4. AC4: aksesibilitas penuh: indikator fokus tetap terlihat (focus-visible, WCAG 2.2 SC 2.4.7), target tombol minimal 24x24 px (SC 2.5.8), seluruh alur section dapat dioperasikan keyboard, status dan error diumumkan lewat aria-live polite.
  5. AC5: test vitest: komponen jsdom (render daftar, submit sukses optimistic replace, error inline rollback, sembunyi bila API null, alur hapus sukses dan gagal dengan konfirmasi), API test routes komentar v415 tetap hijau penuh (14 kasus) tanpa diubah.
  6. AC6: gates penuh: prisma validate 0 dengan NIHIL migrasi NIHIL perubahan schema, tsc 0, lint 0 error (baseline 9 warning), build 0, vitest scope hijau, em dash 0 di baris subtotalan, NIHIL dependency baru, pure core terjaga (tanpa kode komersial), scope tanpa file scratch.
- **Non-Goals:** tanpa edit komentar setelah kirim (hapus plus tulis ulang), tanpa reaksi atau mention, tanpa notifikasi email atau digest, tanpa soft-delete kolom (koreksi feasibility wake-179), tanpa moderation admin, tanpa komentar pada objek lain (families, sources), tanpa main/staging.
